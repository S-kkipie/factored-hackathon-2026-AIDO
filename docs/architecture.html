AI-first banking customer service: system architecture

AI understands and writes; deterministic code decides and acts. Six views: where data flows, how one conversation turn moves through the graph, how the system is measured, how it is deployed on GCP, how LangGraph runs inside the container, and how the agent harness contains the model.

1 · Data and request flow

The offline pipeline turns the organizer CSVs into a read-only serving database. At runtime every data access passes through the tools layer, and only masked fields leave the container.

2 · One conversation turn

Every edge is code. Gemini is called in three nodes only, and the policy node is the single place that decides between acting, confirming and escalating.

3 · How it is measured

Baseline and proposed system replay the same frozen scenarios. The only architectural difference is the policy gate between the model and the tools.

4 · Deployment on GCP

Data never travels through GitHub: the image is built from the developer machine with serving.sqlite inside, and GitHub only runs tests. One Cloud Run container serves both the web app and the API.

5 · LangGraph runtime inside the container

Each session is a LangGraph thread. The graph checkpoints after every node, so an interrupt can wait minutes for the customer or a human agent and resume exactly where it stopped.

6 · Agent harness and guardrails

The model is boxed in: it never sees the database, never holds a tool, and everything it emits passes a code gate before it can change state or reach the customer. Each attack class has a named gate that stops it, and the eval harness asserts that gate fired.
